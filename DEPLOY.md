# Развёртывание на сервере

## Почему не Vercel

Vercel — это serverless-платформа: функции живут максимум 10–60 секунд (максимум ~5–13 минут
на платных тарифах), файловая система между запусками стирается, фоновых процессов нет.
Этот скрипт не подходит под такую модель:

- один цикл сбора занимает 10+ минут в браузере (Playwright с Chromium весит ~1 ГБ — в лимит
  функции не влезает);
- рассылка идёт с паузами 60–90 сек между сообщениями и отдыхом по 15 мин — это часы
  непрерывной работы;
- session-файл Telegram, leads.json, processed.txt должны сохраняться между запусками.

Нужен обычный постоянно работающий контейнер. Ниже два способа.

## Вариант 1 (рекомендую): любой VPS с Docker

Подойдёт самый дешёвый VPS (1 CPU / 1–2 ГБ RAM, Ubuntu 22/24) за ~150–300 ₽/мес.

```bash
# 1. Установить Docker (один раз)
curl -fsSL https://get.docker.com | sh

# 2. Скопировать проект на сервер, например через scp/git
#    (файлы: main.py, requirements.txt, Dockerfile, docker-compose.yml)
scp -r ./3333 user@СЕРВЕР:/opt/tg-outreach

# 3. На сервере — папка данных и файл сессии Telegram (ВАЖНО: там логин аккаунта!)
cd /opt/tg-outreach
mkdir -p data
scp session_sender.session user@СЕРВЕР:/opt/tg-outreach/data/   # со своего компьютера

# 4. Собрать и запустить (работает 24/7, перезапуск сам)
docker compose up -d --build

# 5. Смотреть логи
docker compose logs -f
```

Если файла сессии нет, залогиниться один раз прямо на сервере (пришлёт код в Telegram):

```bash
docker compose run --rm app python main.py --selftest
docker compose up -d
```

Остановка/обновление:

```bash
docker compose down                      # остановить
docker compose up -d --build             # пересобрать после правки main.py
```

Все данные живут в папке `data/` на сервере (сессия, leads.json, processed.txt,
archived.txt) — переживают перезапуски и пересборки.

## Вариант 2 (без своего сервера): Render

1. На компьютере получите строку сессии (это логин вашего аккаунта, никому не показывайте):

   ```bash
   python main.py --export-session
   ```

2. На render.com → New + → **Blueprint** → подключите репозиторий `tg-outreach`
   (в репозитории лежит `render.yaml` — план, диск и переменная подхватятся сами).
   При деплое Render попросит вставить `SESSION_STRING` — вставьте строку из шага 1.

   Вручную (без blueprint): New + → **Background Worker** → выберите репозиторий →
   Runtime: Docker → Disks: добавить диск с путём монтирования `/app/data` →
   Environment: `SESSION_STRING` = строка из шага 1.

3. Deploy. В логах увидите цикл: сбор по нишам → рассылка → архив ссылок в «Избранное».
   Повтор каждые 6 часов (`--every-hours` меняется в `render.yaml`/настройках или в конце
   Dockerfile).

Нюансы:
- тариф Starter (512 МБ RAM) может не хватать для Chromium — если воркер падает
  с OOM, переключитесь на Standard (2 ГБ);
- со строкой `SESSION_STRING` файл сессии не нужен вообще;
- чтобы Render перечитал код после правок — просто push в GitHub, деплой перезапустится сам.

## Как это работает в контейнере

- Запускается непрерывный режим: цикл «сбор по нишам → рассылка → архив ссылок в
  „Избранное"» повторяется каждые 6 часов (меняется флагом `--every-hours` в `command`
  docker-compose.yml).
- Город и ниши: флаги `--city` / `--niches` в `command` docker-compose.yml (см. пример там же).
- Ошибка одного цикла не убивает контейнер: через 10 минут начнётся следующая попытка.
- Чтобы отправлять не больше N сообщений за цикл, добавьте `--limit N` в `command`.
